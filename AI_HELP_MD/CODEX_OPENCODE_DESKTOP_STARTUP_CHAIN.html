OpenCode Windows Desktop Debug Chain

从 VSCode 绿色运行按钮到 Electron main、sidecar、opencode server

这张图把两件事拆开：先是 VSCode 的 preLaunchTask 做构建；构建成功后，VSCode 才启动 Electron。sidecar.js 不是 build 时运行的，它是在 Electron main 进程启动后由 utilityProcess.fork 拉起来的。

谁触发 electron.vite.config.ts 命令是 electron-vite build。electron-vite CLI 会默认查找并加载 electron.vite.config.ts。
build 怎么变成 run build 不会自己 run。VSCode 等 preLaunchTask 完成后，继续执行 launch.json 的 runtimeExecutable。
sidecar 什么时候运行 Electron main 进程运行后，走到 spawnLocalServer()，用 utilityProcess.fork(out/main/sidecar.js) 启动。
构建阶段 - preLaunchTask
运行阶段 - VSCode launch

通信矩阵

方向 通信方式 代码位置 传递内容
VSCode -> PowerShell VSCode Task Shell .vscode/tasks.json 执行依赖安装和构建命令。
VSCode -> Electron main Node Debug launch .vscode/launch.json runtimeExecutable=electron.exe，args=["."]，OPENCODE_CHANNEL=prod。
main -> sidecar utilityProcess.fork + child.postMessage src/main/server.ts type=start、host、port、password、userDataPath、needsMigration。
sidecar -> main parentPort.postMessage + stdout/stderr pipe src/main/sidecar.ts sqlite 进度、ready、error、日志输出。
renderer -> main Electron IPC：ipcRenderer.invoke / ipcMain.handle src/preload/index.ts、src/main/index.ts 调用 await-initialization，拿 sidecar 的 url、username、password。
renderer -> sidecar server HTTP + Basic Auth src/renderer/index.tsx 使用 http://127.0.0.1:<port> 连接本地 opencode server。

最短结论

构建链路

launch.json preLaunchTask -> tasks.json -> bun run build --sourcemap -> prebuild.ts -> build-node.ts -> electron-vite build -> electron.vite.config.ts -> 生成 out/main/index.js 和 out/main/sidecar.js。

运行链路

preLaunchTask 成功后，VSCode 执行 electron.exe . -> Electron 读 package.json main -> 运行 out/main/index.js -> main 调用 utilityProcess.fork(out/main/sidecar.js) -> sidecar 调 Server.listen()。

本页面只解释当前 VSCode “OpenCode Prod: Main Entry” 启动配置。它不是 CLI 的 opencode serve 路线； CLI 路线才会直接经过 packages/opencode/src/index.ts 的 yargs 命令入口。
